# 完美平台（WMPVP）token 抓包说明

## 为什么需要抓包

完美平台查战绩的接口（`api.wmpvp.com/api/csgo/home/...`）都要求请求头里带 `token`。
这个 token **没有任何自动获取的途径**（2026-09 逐条排查确认）：

| 尝试过的路子 | 结果 |
|---|---|
| 网页登录 `pvp.wanmei.com/login/steam` | 走到 `passport.pwesports.cn` → `store.steampowered.com`（Steam OAuth），**本机访问不到 Steam** |
| CS 网页版 F12 抓 | CS 网页版根本不调 `api.wmpvp.com`（网页版只有广告页，调它的全是 DOTA2 站代码） |
| 客户端本地文件 `C:\r0_arena\cfg\user_login.txt` | 有明文 token，但**那是 R0 平台的**且已过期；完美客户端自己的缓存是服务端 AES 加密的 |
| 客户端日志 | 变种 XOR 混淆，且即使解开也是过期会话 |
| refresh / login 端点 | 完美**不存在**可调的这类端点 |
| `gate.wmpvp.com` | 本机网络不可达 |

**结论：只能抓包。** 抓到一次后写进 `state/wmpvp-token.json`，机器人就一直能用（token 有效期实测约 5 个月）。

---

## 抓包原理

```
完美客户端 ──TLS──> api.wmpvp.com
                     ↑
            hosts 把它指到 127.0.0.1
                     │
              本地抓包代理（本仓库脚本）
              用自签证书做 TLS 终端 → 解密 → 读出 token 头
                     │
                     └──> 原样转发给真实 api.wmpvp.com
```

只拦 `api.wmpvp.com` 一个域名；顺带转发 `appengine.wmpvp.com`（搜索接口）。
抓到 token 自动写入 `state/wmpvp-token.json`（旧 token 会先备份）。

## 用法（三步）

### 1. 装完美客户端

安装包**已经下载好了**：
`C:\Users\zjin6\AppData\Local\perfectworldarena-updater\pending\perfectworldarena_win32_v1.0.26081312_0.exe`

直接双击安装（它 `isAdminRightsRequired: false`，不需要管理员）。

### 2. 一键抓包

双击：

```
D:\qq-bridge\抓取完美token.bat
```

它会：请求管理员权限（**只需点一次"是"**）→ 生成证书 → 装信任根 + 改 hosts → 启动代理。

然后**启动完美客户端并登录**。代理会打印：

```
  ✅ 抓到 token（来源: request header token）
     已写入 D:\qq-bridge\state\wmpvp-token.json
```

看到这行就可以 **Ctrl+C** 停掉代理。

### 3. 还原 + 自检

```powershell
# 还原 hosts 和证书信任（需要管理员，会再弹一次 UAC）
powershell -File D:\qq-bridge\scripts\wmpvp-uninstall-capture.ps1

# 自检 token 是否有效、能否查询
node D:\qq-bridge\scripts\check-wmpvp-token.mjs
```

自检会实际调一次接口验证，并打印段位/天梯分。

## 手动方式（不想用上面的脚本时）

用 Reqable / Charles / Fiddler / mitmproxy 任意一个：
1. 装上并让系统信任它的根证书
2. 启动完美客户端、登录
3. 在抓包工具里找发往 `api.wmpvp.com` 的请求
4. 复制**请求头**里的 `token` 字段，写进 `state\wmpvp-token.json`：

```json
{ "token": "粘贴到这里" }
```

## 注意事项

- **抓完一定要跑 uninstall**：否则 wmpvp 域名一直指向本机，客户端会连不上。
- `capture.jsonl` 里有完整请求头/URL（含 token），抓完删掉。
- 证书根 `CN=QQBridge WMPVP Capture CA` 有效期 10 年，可重复使用（重抓不用重新装信任根）。
- 443 端口需要管理员才能绑定——这是 Windows 的限制，不是脚本的问题。
- 如果客户端走的是**证书固定（pinning）**，这套会失败（表现为客户端登录报网络错误）。
  真遇到就走"手动方式"用 Reqable（它对付 pinning 也不行，但能确认请求长什么样）。

## 踩过的坑（改脚本前必读）

### 1. 要拦的是 `pwaweblogin.wmpvp.com`，不是 `api.wmpvp.com`

客户端查战绩走的是 `pwaweblogin.wmpvp.com/user-info/*`，
只拦 `api.wmpvp.com` 会**一条都抓不到**（页面照样能显示数据，因为客户端直接连了公网）。

定位方法：
```powershell
# 看客户端的外连 IP
Get-NetTCPConnection -State Established | Where-Object { $_.OwningProcess -in (Get-Process 完美世界竞技平台).Id }
# 再用公共 DNS 逐个反查是哪个域名
Resolve-DnsName <ip> -Server 223.5.5.5
```

### 2. token 在 URL query 里，不在请求头里

客户端把凭据放在 query：`...?access_token=097819b5...9447`。
所以抓取逻辑**必须同时看 URL 和 header**，只看 header 会静默漏掉。
另外 query 里的 `jt` 是 JWT，payload 的 `a` 字段就是同一个 token。

### 3. hosts 文件被清空的事故（已修，务必注意）

这台机器的 `hosts` **原本就是 0 字节**（第一次检查时 `Select-String` 返回空，
被误判成"没有相关条目"）。而 `Get-Content`（对空文件返回 `$null`）→ `Where-Object` → `Set-Content`
这条链路会把空文件原样写成空文件，看起来还"成功"了。

**现在已全部改用 .NET 文件 API**（`[System.IO.File]::ReadAllLines/WriteAllLines`），
并且 uninstall 在结果为空时**拒绝写入**。另外从 WinSxS 恢复了 Windows 原版 hosts：

```powershell
powershell -File D:\qq-bridge\scripts\restore-hosts.ps1   # 需要管理员
```

> 改任何操作 hosts 的脚本时，**不要用 `Get-Content` / `Set-Content`**。

### 4. 抓包期间自检脚本会绕回本机

hosts 把域名指到 127.0.0.1 后，`check-wmpvp-token.mjs` 如果用普通 `fetch` 会连到本机代理。
所以它用**公共 DNS 解析真实 IP 后直连**（`rawRequest()`），在抓包期间也能正常自检。

### 5. 客户端无法用 CDP 调试

装的是 Electron（`完美世界竞技平台.exe` v1.0.26091013），但：
- `--remote-debugging-port=9222` 启了**不开端口**（客户端自己屏蔽）
- 7 个监听端口（8089 小游戏服务、55599、13031、50000/50001、55555/55556）无 CDP 指纹
- `--remote-debugging-pipe` 被**单实例机制**挡住
- 客户端受**看门狗/反作弊守护**，`taskkill /F /T` 后立刻以新 PID 重启

所以抓包是唯一可行的自动化路径。
